# 修 BUG 规则（开工前必读）

> 背景：这个项目之前多次出现「修一个坏几个」。本文件是强制流程，每次修 BUG 前从头看一遍，
> 修完按第 3、4 节逐项验证。违反流程导致的返工，比修 BUG 本身更贵。

## 0. 铁律

1. **先看后改**：不猜、不凭印象改。先把完整数据流读一遍，确认根因再动代码。
2. **一次只修一个根因**：不顺手重构、不清理无关代码、不格式化无关文件。
3. **修完必须证明旧功能没坏**：按第 4 节回归清单逐项过，不能只看修的这一个点。
4. **必须用 exe 发布版验证**：脚本版通过不算完，要用 `build\release.ps1` 编译出的 exe 在真实实例上看效果（用户明确要求）。
5. **不确定先问用户**：涉及用户数据、第三方软件配置、删除/覆盖操作，先确认再做。
6. **如实报告**：环境限制、没验证到的部分、残留风险，都要说清楚，不许含糊宣布"修好了"。

## 1. 定位阶段

1. **复现并记录**：版本、时间、实例号、操作路径、现象；截图/日志（`_dist\logs\diag.log`、`crash.log`、`guard-*.csv`）。
2. **画数据流**：输入（adb/MuMuManager/进程/WMI）→ 采集/缓存（`lib\10-data.ps1` 等）→ 状态行对象 → UI（`30-ui` / `32-shell` / `33-render`）→ 远程/手机端（`60-remote`）→ 动作（`20-actions`）。
3. **区分症状与根因**：症状在 UI，根因可能在采集字段、定时器、后台线程、配置迁移。
4. **列出该字段/函数的全部消费者**（`grep` 全仓库，含 `tests\`、`MuMuGuard.ps1`、`Waker.ps1`、`Restart-Instance.ps1`），改动前先知道会影响谁。
5. **必要时写最小验证脚本**：临时放 `_build\` 或 `%TEMP%`，不提交仓库。
6. **对比历史**：`_backup\`、`_backup_*/` 里有旧版本代码，可用于对比行为变化。

## 2. 修改阶段

1. **全局搜索再动手**：
   - 函数名：`Select-String -Pattern 'function '`（防止同名函数互相覆盖，见第 6 节事故：Test-GameForeground）。
   - 字段/属性名：PowerShell 对不存在的属性返回 `$null`，不会报错 → 极易静默失效（事故：`$row.MemMB` vs `$row.Private`）。
   - 配置项：新增/改名字段要同时处理旧配置默认值。
2. **纯逻辑放 `lib\90-pure.ps1`**：不依赖 WPF/全局状态，能单测；IO/UI 分开放。
3. **禁止空 catch 吞错**：关键路径至少 `Write-Diag`；绑定错误、属性访问错误不能静默。
4. **同名/同义函数只能有一个入口**；新增函数名先全仓库搜索确认唯一。
5. **数据口径变化必须全套同步**：采集字段、显示换算、环刻度、告警阈值、手机端字段、测试期望值、README 说明（事故：内存合并 MuMuVMMHeadless 后如果不调刻度/阈值，会误报刷屏）。
6. **PowerShell 5.1 兼容清单**：
   - 每个 `.ps1` 必须 UTF-8 BOM（改完先跑 `Check-BOM.ps1 -Fix` 再复检）。
   - 没有 `Join-String`；没有三元运算符。
   - `"$i:"` 会被解析成驱动器 → 用 `"${i}:"`。
   - 单字母函数名/变量名避开 `R`（`Invoke-History` 别名）等冲突。
   - `@($raw | ConvertFrom-Json)` 会把整个数组包成一项 → 先 `$j = $raw | ConvertFrom-Json`，再判断数组逐个处理。
   - 中文/引号/`su -c` 拼接要实测，不能想当然。
7. **第三方软件**（xxYun、MuMu 本体）：
   - 不直接改它的数据库/配置；确需改先备份、征得用户同意、改完恢复原状并说明。
   - 不伪造鼠标/键盘输入（本机环境合成输入被限制，实测无效），界面操作交给用户，我们负责看截图/日志指导与验证。
8. **改动最小化**：只改必要文件；不删用户数据；不覆盖用户配置；不提交 `_dist`、`_build`、日志、截图等产物（除非仓库本来跟踪）。

## 3. 验证阶段（每项都要做）

1. `tests\Run-Tests.ps1`：全部通过；新增/修改逻辑必须补单测或自检项。
2. `Check-BOM.ps1 -Fix` 后再跑 `Check-BOM.ps1`；`tests\Check-Syntax.ps1` 通过。
3. `build\release.ps1` 成功；smoke test 自检项全部 PASS（当前 33 项，`自检 33 项全过`），窗口/画面正常。
4. **exe 实机验证**：用 `_dist\MuMuGuard.exe` 在真实实例上跑，覆盖被修改的路径（面板概览、实例管理、实例详情、紧凑视图、手机端、告警/事件、日志、持久化），保留日志或截图证据。
5. **数值类修复**：至少采样两轮（多个时间点）确认数值区间，并测边界：0 / 超大 / 离线 / 休眠 / 多开。
6. **回归清单**（第 4 节）逐项 PASS/FAIL/SKIP，写进提交信息或答复；FAIL 必须修或说明原因。

## 5. 发布与交付

- **版本号**：修复只改末尾数字（如 `2.1.1 → 2.1.2`）。
- **公告/发布说明**：小修复写「修复了一些问题」，不要写长文；有明确用户可见变化可加一句简单说明。代码库和群号照旧保留，其他从简。
- **提交信息**写清：根因、改动点、影响面、验证证据（数字/命令）。
- **推送**：GitHub HTTPS 直推常被墙 → 用 `_build\push-via-api.ps1`（自动建 tag）；发布 `gh release create`，核对 asset digest 与本地 sha256 一致。
- **交付答复**：说明版本、改了什么、验证证据、当前运行状态、未完成/风险项。

## 6. 事故档案（警钟，勿重犯）

1. **同名函数覆盖**：`90-pure` 的 `Test-GameForeground` 与 `63-res` 同名 → 加载顺序覆盖 → 前台保护失效，游戏前台也被休眠。
2. **空 catch 吞绑定错误**：函数覆盖后参数绑定失败被空 catch 吞掉，没有任何日志，排查了很久。
3. **属性名笔误**：`33-render` 读 `$row.MemMB`，行对象里实际叫 `Private` → 详情页「内存占用」行永远不显示，且被 try/catch 静默。
4. **新进程架构漏算**：MuMu 新引擎把 guest 内存移到 `MuMuVMMHeadless.exe`，只统计 `MuMuNxDevice.exe` → 6G 实例显示 0.1GB，内存告警失效。
5. **口径变化未同步阈值**：合并内存后若不调刻度/告警，会把正常实例全部误报。
6. **PowerShell 5.1 编码/语法坑**：缺 BOM 按 GBK 解析中文报错；`$i:` 被当驱动器；`Join-String` 不存在。
7. **第三方配置直接改**：直接改 xxYun 数据库造成孤儿映射，页面一直读取/卡死；恢复备份才修好。第三方只读为主，先备份、先征得同意。
8. **合成输入不可用**：本机环境鼠标/键盘模拟输入被限制（连自建 WinForms 按钮都点不动）→ 不要承诺替用户点 UI；让用户操作，我们截图/日志指导。
9. **验证不充分**：只跑脚本版就宣布完成 → 用户要求以后一律用 exe 发布版在真实环境验证。
10. **自动唤醒后实例长时间不出现**：实例重扫被 `WindowState -ne 'Minimized'` 挡住，面板最小化后新唤醒的实例永远进不了采集清单；唤醒器也没有通知面板。修复：后台 30 秒重扫（不看窗口）、唤醒器写 `wake-notify.json` 通知面板立即刷新并强制采集、窗口恢复立即刷新、idle 采集间隔从 120 秒降到 30 秒。10. **自动唤醒后实例长时间不出现**：实例重扫被 `WindowState -ne 'Minimized'` 挡住，面板最小化后新唤醒的实例永远进不了采集清单；唤醒器也没有通知面板。修复：后台 30 秒重扫（不看窗口）、唤醒器写 `wake-notify.json` 通知面板立即刷新并强制采集、窗口恢复立即刷新、idle 采集间隔从 120 秒降到 30 秒。
11. **采集线程被 MuMuManager 卡死**：MuMuManager adb/sh 在实例关机/切换阶段会无限挂住，旧代码直接同步调用、没有超时也没有心跳看门狗，导致整个采集线程停摆数小时（表现为「检测不到 ADB」、紫孔雀掉线不恢复）。修复：worker 内所有 MuMuManager/adb 调用走带超时的 `Invoke-ExeTimeout`（超时杀进程树）；主计时器用 `Test-SyncHeartbeatStale` 检查心跳，超过 120 秒自动重启采集线程。
