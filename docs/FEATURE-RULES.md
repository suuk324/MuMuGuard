# 加功能规则（开工前必读）

> 背景：这个项目加功能时多次把旧功能带坏（同名函数覆盖、后台线程传参缺失、手机端字段漏补、
> 设置项保存后不生效等）。本文件是强制流程：加功能前从头看一遍，发布前按回归清单逐项验证。

## 0. 铁律

1. **新功能不允许改变旧行为**：新页面/新字段默认不影响旧路径；旧实例、旧配置、旧手机端缓存都要能用。
2. **默认安全、可降级**：新功能出错不能中断看护/刷新/休眠等核心流程；必须 try/catch + `Write-Diag`。
3. **数据向后兼容**：新增配置项有默认值；`ConfigVersion` 需要时做迁移并备份旧文件；不清空旧数据。
4. **先设计后编码**：写清需求边界、数据流、影响面、测试计划，再动文件。
5. **必须用 exe 发布版验证**：脚本版跑通不算完成；用 `build\release.ps1` 的 exe 在真实实例上走通新功能，并回归旧功能。
6. **不确定先问用户**：涉及删除/覆盖用户数据、改第三方软件配置、发布行为变更，先确认。

## 1. 设计阶段

1. **需求写清楚**：做什么、不做什么、入口在哪、用户怎么用、失败时看到什么。
2. **数据流设计**：数据从哪来（adb/MuMuManager/WMI/进程/文件）→ 采集缓存 → 状态字段 → UI 页面 → 远程/手机端 schema → 持久化（config/sleep/trend/日志）。
3. **兼容性清单**：
   - 旧 `config.json` 缺新字段时的默认值；
   - 旧 `sleep.json` / `trend.json` / 事件 CSV 可读；
   - 手机端旧页面（缓存）对新字段不报错；
   - exe 版和脚本版共用 `_dist` 数据，两边都要能用。
4. **影响面清单**：列出将改的文件/函数/页面/远程字段/设置项/公告/README；列出可能受影响的旧功能（见第 5 节）。
5. **命名检查**：新函数先全仓库搜索，禁止与现有函数同名（PowerShell 后加载覆盖前者）；新 `$script:` 变量在 `MuMuGuardApp.ps1` 初始化并在采集结束清理缓存类状态。
6. **不引入外部依赖**：不装系统服务、不改 MuMu 本体、不新增必装组件；网络/第三方 API 只做可选增强，失败能降级。

## 2. 实现阶段

1. **分层放置**：
   - 纯逻辑（可单测）→ `lib\90-pure.ps1`；
   - 数据采集/缓存 → `lib\10-data.ps1`、`lib\05-instances.ps1`；
   - 动作/写文件 → `lib\20-actions.ps1`；
   - UI/渲染 → `30-ui` / `32-shell` / `33-render`；
   - 远程/手机端 → `60-remote`。
2. **UI 线程不做重活**：WMI/IO/OCR 放后台 runspace；后台线程需要的文件/参数显式传入（事故：63-res 的 `$DataDir` 没传导致写错目录）。
3. **性能预算**：UI 刷新约 5 秒一轮；不要每个 tick 都查 WMI/CIM；大列表分页/缓存；新增定时器要能随设置项实时生效（`Apply-SettingSideEffect`）。
4. **失败降级**：新功能异常只影响自己，不阻塞实例采集、看护、休眠、手机端主流程；错误要写 `diag.log`。
5. **数据安全**：新增写文件用原子写（临时文件 + Move-Item -Force）；改用户/第三方配置前先备份；删除类操作必须二次确认。
6. **日志与诊断**：新功能关键路径加 `Write-Diag`/事件记录，便于以后排查；不记录用户隐私/密钥。
7. **设置页**：新增可配置项要加说明文案、单位、默认值，并确认保存后立即生效（不用重启面板才生效）。
8. **手机端/远程**：新增字段要有默认值、旧页面兼容；状态快照体积控制（截图只按需发）。

## 3. 文档与公告

- README 新增 `X.Y.0 更新了什么` 一节，简单写加了什么，不写长文。
- 公告（`lib\34-announce.ps1`）同步：标题版本号 + 简单功能说明；代码库和群号保留，其他从简。
- 设置页/界面文案与 README 保持一致。
- 新增/变更的对外行为，在答复里明确告知用户。

## 4. 版本与发布

- **版本号**：加功能改中间位，末位归 0（如 `2.1.1 → 2.2.0`）；修复只改末位（`2.2.0 → 2.2.1`）。
- **测试**：`tests\Run-Tests.ps1` 全过（新逻辑必须有单测）；自检项需要时补充（`Invoke-UiSelfTest` / `tests\Test-Features.ps1`）。
- **构建**：`Check-BOM.ps1 -Fix` → `Check-BOM.ps1` → `tests\Check-Syntax.ps1` → `build\release.ps1`（内含 smoke test，自检必须全 PASS）。
- **exe 实机验证**：真实实例上走通新功能 + 第 5 节回归清单，保留证据。
- **推送/发布**：`_build\push-via-api.ps1` 推 master 和 tag；`gh release create` 上传 exe / sha256 / 源码 zip，核对 digest。

## 6. 警钟（历史事故，勿重犯）

1. **改公共函数/字段把旧功能带坏**：同名函数覆盖（`Test-GameForeground`）导致前台保护失效；加功能改公共采集字段要先列全部消费者。
2. **后台线程缺参数**：`63-res` 后台 runspace 没传 `$DataDir`，截图写到错误目录，界面读不到。
3. **手机端字段漏补**：休眠/关机实例单独补列表时漏 `res` 字段，手机只显示「尚未采集」。
4. **设置项保存后不生效**：改了配置但定时器/UI 没重新应用 → 必须走 `Apply-SettingSideEffect`。
5. **口径变化不同步**：新增内存/资源口径若不同步刻度、阈值、手机端字段，会误报或显示错误。
6. **版本/公告不同步**：VERSION、appVersion、界面版本号、README、公告要一起改（release.ps1 只同步 VERSION → appVersion）。
7. **UI 自动点击不可用**：本机环境合成输入被限制，自检用 `RaiseEvent`（WPF 内部事件）可以，不要试图模拟全局鼠标键盘。
8. **PS2EXE 打包坑**：脚本里直接内嵌很大的 `scriptblock`（如后台 worker）会让编出的 exe 无法启动（无日志、退出码 -1，Windows 事件报 manifest 无效）；大段脚本/预设内容改成 base64 字符串再 `[scriptblock]::Create`，并在编译后等 8 秒再跑冒烟测试（刚写出的 exe 会被短暂占用，报 Access denied / SxS 错误）。
